# TMDL Reference Guide (Tabular Model Definition Language)

## When Used
TMDL (Tabular Model Definition Language) is the **textual, human-readable, Git-friendly serialization format** for Microsoft's Analysis Services Tabular Object Model (TOM) at compatibility level 1605+:

- **Power BI semantic models** (both in `.pbip` Power BI Projects and standalone datasets deployed via [Tabular Editor](https://tabulareditor.com/) CLI / [Microsoft.AnalysisServices.TMDLReaderWriter](https://learn.microsoft.com/en-us/dotnet/api/microsoft.analysisservices.tmdl))
- **Azure Analysis Services (AAS) / SQL Server Analysis Services (SSAS) Tabular 2022+**
- **Fabric Lakehouse / Warehouse semantic models**

Specifically use TMDL when you need:
- **Version-controlled semantic model definitions** in CI/CD pipelines (replacing opaque `.bim` JSON blobs)
- **Code review of measures, relationships, roles, calculation groups, data sources**
- **Scripted bulk updates** (rename columns across 50 measures, generate calc-group items, etc.)
- **Deterministic deployment** via `.pbip` / TMDL + deployment pipelines
- **Lineage and documentation from source** (TMDL preserves description/format-string/translated names)
- **Power BI Desktop "save as project" (PBIP) round-tripping** — Desktop writes TMDL directly

## When NOT Used
- **Legacy SSAS Tabular < 2022 / compat level <1605** — use `.bim` JSON
- **ETL / data transformation** — TMDL is a *model definition* language, not a data-processing language (use SQL, dbt, Spark, Dataflows, Data Factory)
- **Report / visual definitions** (Power BI `.pbir` visual layout) — TMDL covers the *semantic model* only; visuals are `.pbir`/`.pbidesign` JSON
- **Power BI workspaces, capacity, workspace access provisioning** — use REST APIs, Terraform AzApi, Az PowerShell; TMDL defines objects *inside* a dataset
- **Calculation logic that should live in the warehouse** (e.g., complex joins / cleaning) — do it in SQL/dbt, not as 1000-line TMDL-partition M/SQL expressions
- **Quick one-off measure edits shared via Slack** — paste the measure DAX; editing a full TMDL commit is overkill

## Common Mistakes

1. **Editing `.pbip` TMDL manually without Tabular Editor / TMDL validator** — a single indentation error or duplicate key breaks the entire model parse; TMDL has strict grammar (see Syntax Reference below).
2. **Committing user-specific workspace/server paths** — do not hardcode connection strings with tenant IDs, keys, or local folder paths; use [parameterized data sources](https://learn.microsoft.com/en-us/power-bi/connect-data/desktop-data-source-parameters) + environment-scoped deployment.
3. **Ignoring naming conventions on objects** — `Table: fct_sales`, `Column: order_date`, `Measure: Revenue YoY %`; inconsistent naming across devs makes regex-based refactors impossible and lineage unreadable.
4. **Relationships without explicit cardinality + cross-filter direction** — default "Single" / "Many to One (*:1)" autodetect is wrong ~20% of the time; explicitly declare.
5. **Embedding secrets in provider data source expressions** — use Entra ID service principals, OAuth, Key Vault references; never paste a storage account key in TMDL.
6. **Deleting a referenced column without checking measure/calc-group lineage** — dozens of measures break silently in reports; use Tabular Editor's "Show dependencies" before removal.
7. **Mixing manual edits and Power BI Desktop saves without rebase** — Desktop re-serializes TMDL; if two branches edited the same partition/measure you get messy merge conflicts.
8. **Display folders as `\`-separated string literals with wrong case** — TMDL is case-sensitive for object references; `Revenue\YoY` and `Revenue\yoy` are two distinct folders.
9. **Deploying TMDL directly to PROD via Power BI Desktop Publish** — bypasses validation, tests, and change log; go through DEV → CI pipeline → deployment pipeline.
10. **Calculation groups without explicit precedence and format-string expressions** — two calc groups with same precedence = non-deterministic application order; reports may silently pick wrong result depending on query path.

## Trade-offs

| Decision | Advantages | Disadvantages |
|----------|-----------|---------------|
| **TMDL vs `.bim` JSON** | TMDL: git-friendly (line-per-object), 2–10× smaller, human-readable diffs, supported by `git diff` tools. `.bim`: universal, works at older compat levels, tooling is 10 years mature. | `.bim` diffs are noisy (huge single line JSON). TMDL: newer ecosystem; fewer parsers/validators outside Microsoft stack. |
| **TMDL in `.pbip` vs TE CLI deploy** | `.pbip` round-trips with PBI Desktop; every dev uses familiar tool. TE CLI: can merge/transform model fragments across repos, inject env variables, bulk edit DAX pre-deploy. | `.pbip` couples report + model; you can't deploy only the model easily without also deploying reports. |
| **Hand-written TMDL vs generated by Tabular Editor** | Hand-write: full control, no GUI. TE GUI: discoverability of properties, autocomplete for DAX, "save as TMDL" without syntax errors. | Hand-write: slow, error-prone. TE-generated: sometimes adds unnecessary properties that inflate diff noise. |
| **Inline partition SQL vs shared M expressions** | Inline SQL: one file per partition; one-command change. Shared M/PQ: DRY, reusable source for multiple tables. | Inline SQL: duplication when 30 partitions use same query with different parameters. M expressions: harder to compare SQL changes across commits. |
| **Calculated Tables vs SQL materialized in warehouse** | CT in TMDL: no ETL dependency, instant iteration during dev. Warehouse: refresh performance 10–100× better, reusable across datasets, testable. | |

### Table Definition (fct_Sales.tmdl)

```tmdl
table fct_Sales
    description = "Transaction-level grain sales fact; one row per order line."
    lineTagTag = 301
    partitions
        partition "Sales 2024"
            description = "Fiscal year 2024 sales partition; incremental daily refresh."
            mode = Import
            source
                partitionSource = "m"
                expression =
                    let
                        Source = Sql.Database(DatabaseServer, DatabaseName),
                        Sales = Source{[Schema="mart",Item="fct_sales"]}[Data],
                        Filtered = Table.SelectRows(Sales, each [sale_date] >= #date(2024,1,1) and [sale_date] < #date(2025,1,1))
                    in
                        Filtered
        partition "Sales 2025"
            mode = Import
            source
                partitionSource = "m"
                expression =
                    let
                        Source = Sql.Database(DatabaseServer, DatabaseName),
                        Sales = Source{[Schema="mart",Item="fct_sales"]}[Data],
                        Filtered = Table.SelectRows(Sales, each [sale_date] >= #date(2025,1,1) and [sale_date] < #date(2026,1,1))
                    in
                        Filtered
    columns
        column sale_id
            dataType = Int64
            summaryBy = Count
            isAvailableInMdx = false
            description = "Natural PK from OLTP; unique per line."
            lineTagTag = 10
        column sale_date
            dataType = DateTime
            formatString = "yyyy-mm-dd"
            description = "Order placement date (UTC)."
            displayFolder = "Dates"
            lineTagTag = 20
        column customer_key
            dataType = Int64
            isHidden = true
            description = "FK to dim_Customer."
            lineTagTag = 30
        column product_key
            dataType = Int64
            isHidden = true
            lineTagTag = 40
        column order_id
            dataType = String
            dataCategory = "Identifier"
            lineTagTag = 50
        column quantity
            dataType = Double
            formatString = "#,##0"
            lineTagTag = 60
        column unit_price
            dataType = Double
            formatString = "#,##0.00"
            lineTagTag = 70
        column line_amount
            dataType = Double
            formatString = "#,##0.00;-#,##0.00;0"
            lineTagTag = 80
        column is_return
            dataType = Boolean
            lineTagTag = 90
    measures
        measure "Revenue"
            expression = SUM(fct_Sales[line_amount])
            formatString = "#,##0 €;-#,##0 €;0 €"
            description = "Gross revenue on completed lines before returns and discounts."
            displayFolder = "Base"
            lineTagTag = 1001
        measure "Revenue YTD"
            expression = CALCULATE([Revenue], DATESYTD('Date'[Date]))
            formatString = "#,##0 €;-#,##0 €;0 €"
            displayFolder = "Time Intelligence"
            lineTagTag = 1002
        measure "Revenue YoY %"
            expression =
                VAR _c = [Revenue]
                VAR _p = CALCULATE([Revenue], SAMEPERIODLASTYEAR('Date'[Date]))
                RETURN DIVIDE(_c - _p, ABS(_p), BLANK())
            formatString = "0.00 %;-0.00 %;- "
            displayFolder = "Time Intelligence\YoY"
            description = "Year-over-year revenue growth, %; blank if either period missing."
            lineTagTag = 1003
        measure "Order Count"
            expression = DISTINCTCOUNT(fct_Sales[order_id])
            formatString = "#,##0"
            displayFolder = "Base"
            lineTagTag = 1004
        measure "Average Order Value"
            expression = DIVIDE([Revenue], [Order Count], BLANK())
            formatString = "#,##0.00 €"
            displayFolder = "Base"
            lineTagTag = 1005
        measure "Return Rate"
            expression = DIVIDE(CALCULATE([Revenue], fct_Sales[is_return] = TRUE()), [Revenue])
            formatString = "0.00 %"
            displayFolder = "Quality"
            lineTagTag = 1006
    hierarchies
        hierarchy "Sales by Order"
            description = "Browse from order_id to line."
            levels
                level order_id
                level sale_id
```

### Relationships (relationships.tmdl)

```tmdl
relationship fct_Sales_dim_Customer
    fromColumn = fct_Sales.customer_key
    toColumn   = dim_Customer.customer_key
    cardinality  = ManyToOne
    crossFilteringBehavior = SingleDirection
    isActive = true
    name = "fct_Sales → dim_Customer (customer_key)"
    lineTagTag = 5001

relationship fct_Sales_dim_Product
    fromColumn = fct_Sales.product_key
    toColumn   = dim_Product.product_key    ; dimension on ONE side
    cardinality  = ManyToOne
    crossFilteringBehavior = SingleDirection
    isActive = true
    name = "fct_Sales → dim_Product (product_key)"
    lineTagTag = 5002

relationship fct_Sales_Date__Sale
    fromColumn = fct_Sales.sale_date
    toColumn   = Date.Date
    cardinality = ManyToOne
    crossFilteringBehavior = SingleDirection
    isActive = true
    name = "fct_Sales → Date (sale_date) [active]"
    lineTagTag = 5003

relationship fct_Sales_Date__Ship
    fromColumn = fct_Sales.ship_date
    toColumn   = Date.Date
    cardinality = ManyToOne
    crossFilteringBehavior = SingleDirection
    isActive = false                          ; role-playing: use USERELATIONSHIP()
    name = "fct_Sales → Date (ship_date) [inactive]"
    lineTagTag = 5004
```

### Calculation Group (calcgroup_TimeIntelligence.tmdl)

```tmdl
calculationGroup calcgroup_TimeIntelligence
    description = "Standard time intelligence templates; apply to any base measure."
    precedence = 30
    columns
        column "Name"
            dataType = String
            lineTagTag = 1
        column "Format String"
            dataType = String
            lineTagTag = 2
    calculationItems
        calculationItem "Current"
            ordinal = 1
            expression = CALCULATE(SELECTEDMEASURE())
            formatStringExpression = SELECTEDMEASUREFORMATSTRING()
            lineTagTag = 11
        calculationItem "YTD"
            ordinal = 2
            expression = CALCULATE(SELECTEDMEASURE(), DATESYTD('Date'[Date]))
            formatStringExpression = SELECTEDMEASUREFORMATSTRING()
            lineTagTag = 12
        calculationItem "PY"
            ordinal = 3
            expression = CALCULATE(SELECTEDMEASURE(), SAMEPERIODLASTYEAR('Date'[Date]))
            formatStringExpression = SELECTEDMEASUREFORMATSTRING()
            lineTagTag = 13
        calculationItem "YoY %"
            ordinal = 4
            expression =
                VAR _c = SELECTEDMEASURE()
                VAR _p = CALCULATE(SELECTEDMEASURE(), SAMEPERIODLASTYEAR('Date'[Date]))
                RETURN DIVIDE(_c - _p, ABS(_p), BLANK())
            formatStringExpression = "\"0.00 %\""
            lineTagTag = 14
```

### Role / RLS (RegionalSalesRole.tmdl)

```tmdl
modelRole "Regional Sales"
    modelPermission = Read
    members = []          ; AAD groups assigned during deployment; never embed user emails here
    rowLevelSecurity
        tablePermission dim_Employee
            filterExpression =
                PATHCONTAINS(
                    LOOKUPVALUE(dim_Employee[manager_hierarchy_path],
                                dim_Employee[upn],
                                USERPRINCIPALNAME()),
                    dim_Employee[employee_key]
                )
        tablePermission fct_Sales
            filterExpression =
                RELATED(dim_Employee[territory_key]) IN CALCULATETABLE(
                    VALUES(dim_Employee_Territory[territory_key]),
                    USERPRINCIPALNAME() = dim_Employee_Territory[upn]
                )
```

### Data Source (WarehouseSQL.tmdl) — Parameterized, No Secrets

```tmdl
dataSource "WarehouseSQL"
    provider = "SqlServer"
    connectionString =
        "Server=" & DatabaseServer & ";"
        & "Database=" & DatabaseName & ";"
        & "Authentication=ActiveDirectoryServicePrincipal;"
        & "Encrypt=True;TrustServerCertificate=False;Connection Timeout=120;"
    credential =
        kind = "OAuth2"
        path = "//login.windows.net/" & TenantID & "/oauth2/token"
    impersonationMode = ImpersonateServiceAccount
```

## TMDL Syntax Reference (Quick)

- **Comments:** `; single-line comment` or multi-line (unsupported, use descriptions)
- **Structure:** Object-type `identifier` then indented `property = value` block; scopes end by dedent (Python-like indentation, typically 4 spaces)
- **Root objects:** `model`, `table`, `dataSource`, `modelRole`, `expression`, `culture`, `perspective`
- **Nested scopes:** `table > {columns, measures, hierarchies, partitions, levels, annotations, calculationItems}`
- **Literals:**
  - Strings: unquoted when single token, `"quoted when has spaces or special chars"`; multiline strings = indent under `expression =` without surrounding quotes
  - Numbers: `42`, `3.14`
  - Enums: `dataType = Int64`, `cardinality = ManyToOne` (case-sensitive)
  - Boolean: `true` / `false`
  - Lists: `[a, b, c]` or one-per-line indented block
- **Object references across files:** Use `TableName.ColumnName` (case-sensitive!) — e.g., `toColumn = dim_Customer.customer_key`
- **Line tags:** `lineTagTag = <int>` is a stable ID that allows refactoring *names* while preserving lineage across saves. NEVER copy-paste line tags; let Tabular Editor/Power BI Desktop assign unique ones, or omit for handwritten TMDL.
- **Entry model.tmdl:** Lists or includes every other root object (actual include syntax varies by tool; often Power BI Desktop emits a root `model` with imports).

## Lineage, Metadata & Display Folders

- **Always fill `description`** on tables, columns, measures, calc-item, roles. It feeds directly into:
  - Power BI "Data hub" hover tooltips
  - `RELATED()` / `INFO.OBJECTS()` DMV queries
  - Automated data dictionaries (export with `Tabular Editor CLI > Save As → Markdown`)
- **Display folders use backslash `\` hierarchy:** `displayFolder = "Time Intelligence\YoY"` → nested folder. Match names consistently across measures (e.g., always `Base`, not `base`/`Basics`).
- **Translations:** `<culture>/fr-FR.tmdl` → override `translatedDescription`, `translatedDisplayFolder`, `translatedName` per locale; never duplicate entire tables.
- **Format strings are critical for users:** Measures default to raw float → export `1234567.89` instead of `1 234 567,89 €`. Always set.

## Source Control & Naming Conventions

### File & Object Names
```
tables/          dim_Customer.tmdl      (prefix dim_ / fct_ / calcgroup_ / ref_ )
dataSources/     WarehouseADLS.tmdl     (system + type)
roles/           RegionalSales.tmdl     (business name, PascalCase)
```

### Columns
- Snake_case / PascalCase is fine, **consistent across project**.
- Hidden FK keys: `isHidden = true`, suffix `_key`.

### Measures
- PascalCase with spaces? → Pascal case like `"Revenue YoY %"` (spaces fine, quoted in TMDL).
- Display folder mandatory.

### Git hygiene
- Don't commit `.pbi/localSettings.json` or personal-refresh tokens.
- Use `.gitattributes` to mark `*.tmdl text eol=lf` to avoid whitespace churn.
- Add a CI step: validate TMDL parses cleanly (TE CLI: `te.exe analyze-model file.tmdl`) *before* merging PRs.

## Deployment & Validation Pipeline

```yaml
# Azure DevOps / GitHub Actions (conceptual)
- task: UseDotNet@2
  inputs: { package: dotnet, version: 8.0.x }
- pwsh: |
    dotnet tool install --global TabularEditor.CLI --prerelease
    te.exe model analyze "$(Build.SourcesDirectory)/dataset/definition/model.tmdl" `
        --validate-objects `
        --validate-dax `
        --throw-on-warning
    te.exe model deploy "$(Build.SourcesDirectory)/dataset/definition/model.tmdl" `
        --workspace "$(WORKSPACE_ID)" `
        --dataset "SemanticModel-DEV" `
        --credential "$(SERVICE_PRINCIPAL)" `
        --refresh-policy Full `
        --what-if          # PR runs: only what-if, no actual deploy
- task: PowerBI@2
  inputs:
    workspaceName:    "BI - PROD"
    pbipPath:         "$(Build.ArtifactStagingDirectory)/semantic-model"
    serviceConnection:"PowerBI PROD SP"
    action:           "Deploy"
```

### Pre-Deploy Validation Checklist (CI)
1. TMDL parses without errors (no duplicate objects, indentation consistent)
2. Every FK column has a matching relationship; orphan FK → fail PR
3. Every `DATE`/`DATETIME` column on a fact has an inactive or active relationship to `Date[Date]`
4. No measure references a column that has been deleted → run `te.exe analyze-model --validate-dax`
5. Calculation group precedence set, no two calc groups share a precedence value
6. RLS roles compile; `CALCULATE` inside RLS filter expressions is banned (performance)
7. Format strings present on all currency / percent / date measures

## How to Test TMDL Definitions

1. **Schema contract test** (Python / pytest + TOM.NET DMV):
   ```python
   EXPECTED_TABLES = {"dim_Customer", "dim_Product", "fct_Sales", "Date", ...}
   def test_expected_tables_present(ssas_client):
       actual = {row["TABLE_NAME"] for row in ssas_client.query_dmv("$SYSTEM.TMSCHEMA_TABLES")}
       assert EXPECTED_TABLES <= actual
   ```
2. **Measure regression tests** via DAX Studio TE scripts (EVALUATE ROW(...) per measure): run same filter matrix (All, US-2024, FR-2023) across dev-proposed vs prod baseline dataset; assert difference < 1e-6.
3. **Relationship integrity**: `EVALUATE` per FK → count of orphan keys must be 0.
4. **RLS smoke-test**: Impersonate every role + several UPNs; assert total number of visible rows is within expected range (never 0 unless intentionally; never > total fact rows — bidirectional filter bug).
5. **Refresh performance benchmark**: Import-mode partitions → refresh dataset; log partition duration; fail CI if any partition slowed > 2× from baseline.
6. **Translations & metadata smoke-test**: Export dictionary; assert 95% of user-facing objects have a description.

## Performance Behavior

| Aspect | Cost Profile |
|--------|-------------|
| Import mode, 100M-row fact, 15 int + 5 string cols | ~1–5 GB Vertipaq compressed; 10–60s full refresh |
| Import with incremental refresh policy | Daily delta: seconds to minutes |
| DirectQuery on 1M-cell query | Translates to 1 SQL → warehouse latency dominates |
| Calculated group × 20 measures × 10 calc items | 200 logical measures stored as ~30 TMDL lines; no additional RAM footprint |
| 5000 hand-written measures | TMDL size ~2–4 MB; parse + deploy: < 1 s |
| 5000 hand-written measures + 10 relationships to high-card dim | SE scan plan bloat on heavy visuals; use Perspectives to hide 90% per user department |

## What to Inspect First (Parse Fail / Bad Deployment / Wrong Numbers)

1. **Indentation consistency** — Did a merge conflict mix 2-space and 4-space indents? TMDL is strictly indent-scoped like Python.
2. **Duplicate `lineTagTag`** — Two objects with same line tag breaks internal references; let TE/PBI Desktop regenerate.
3. **Case-sensitivity of references** — `tOColumn = Dim_Customer.customer_key` when table is spelled `dim_Customer` → model doesn't load.
4. **Duplicate relationship paths** — Adding a second relationship without `isActive=false` → ambiguous path error on deploy.
5. **Secrets printed in CI logs** — Connection string with `password=xxx` → rotation needed; re-check service-principal OAuth config.
6. **Missing calc-group precedence value** → calc items apply randomly; always set explicit precedence (Time=30, Scenario=20, FX=10 etc.)
7. **Partition filter overlap / gap** — `sales 2024` covers 2024-01-01..2024-12-31 inclusive, but `sales 2025` starts 2025-01-02 → Dec 31st 2024 sales counted twice or missing? Always write half-open: `>= start and < next_start`.
8. **Hidden column used in visual** — You deleted `displayFolder` + `isHidden=true` → reports break; use "Analyze in Excel" + DAX Studio trace to find.
9. **Format string literal escaping** — `formatStringExpression = "0.00"` vs `"\"0.00\""` (outer quotes for string DAX value); wrong = raw numeric on screen.
10. **TMDL version / compat level mismatch** — You used a new TMDL feature (e.g., Dynamic format strings in calc group) but target dataset's compat level is 15xx → deploy fails; check workspace capacity release channel.
